# The AI Engineer Roadmap

A **pure AI track**: it deliberately skips classical machine-learning and
data-analytics paths and goes straight into the part of the field you actually build
with — **Large Language Models, Generative AI, and autonomous Agents**. The sequence
mirrors the way the field is learned in 2026: understand LLMs first, then Generative
AI and RAG, then graduate to Agentic AI.

## How to use this roadmap

Every topic follows one simple loop. Repeat it for each lesson:

1. **Understand** — read the lesson and the "what to understand" points until the
   concept clicks.
2. **Study a project** — open a real, mapped project for that topic. Read its
   description, look at the stack, understand *how* it's built.
3. **Build your own** — rebuild it yourself (don't copy-paste), then push it to GitHub
   with a README.

Projects are tagged by difficulty so you always know if you're ready:

- <span style={{color: "#16a34a", fontWeight: 600}}>beginner</span> — do these first;
  they teach the core idea cleanly.
- <span style={{color: "#d97706", fontWeight: 600}}>intermediate</span> — once the
  basics are solid; adds real-world complexity.
- <span style={{color: "#dc2626", fontWeight: 600}}>advanced</span> — production-grade;
  tackle after you've shipped a few projects.

You don't have to build *all* of them — but build **at least one per stage** before
moving on.

## The path at a glance

Nine stages, in order. Stage 0 is a short prerequisite; the real journey is Stages
1–8. Stages 1–3 are LLM basics + apps, 4–5 are the Generative-AI / RAG path, and 6–8
are the Agentic-AI path.

| Stage | Focus | What you can build by the end |
| --- | --- | --- |
| 0 | [Python for AI](#stage-0--python-for-ai) | Run any LLM script, call an API, use Git |
| 1 | [LLM Basics](/docs/llm-basics/what-is-an-llm) | A working chatbot that calls an LLM API |
| 2 | [Calling Models](/docs/calling-models/apis-and-sdks) | Reliable, structured LLM calls from code |
| 3 | [Prompting & LLM Apps](/docs/prompting/what-is-prompting) | Structured, deployed LLM-powered apps |
| 4 | [Retrieval (RAG)](/docs/rag-course/rag-course-overview) | A chatbot that answers from your own docs |
| 5 | [Advanced & Production RAG](#stage-5--advanced--production-rag) | Enterprise RAG: hybrid search, reranking, guardrails |
| 6 | [Fine-Tuning & Open Models](#stage-6--fine-tuning--open-models) | A customized / fine-tuned model in an app |
| 7 | [Agentic AI](#stage-7--agentic-ai) | Multi-agent systems with tools & memory |
| 8 | [AgentOps, MCP & Production](#stage-8--agentops-mcp--production) | Deployed, observable, secure agent systems |

> **Why this order?** Agentic AI means "autonomous systems that use LLMs to plan,
> reason, and act" — so you must master LLMs and RAG first, then graduate to agents.
> Spend the most time on Stages 4, 5, and 7 — that's where the jobs are.

## Stage 0 · Python for AI

You don't need statistics or ML algorithms for this track, but you do need to read
and write Python comfortably, because every LLM and agent framework is Python. Keep
this short — a few weeks — and come back to fill gaps as needed.

**What to learn:** Python core (variables, lists, dicts, loops, functions, classes) ·
working with APIs (HTTP calls, JSON, `.env` for keys) · environments & packages
(venv, pip, requirements) · async basics & error handling · data validation with
Pydantic (typed models → structured, validated outputs) · Git & GitHub · a fast UI
with Streamlit (and a little FastAPI).

**Build-along projects:** a Personal AI Voice Assistant (a JARVIS-style Streamlit app
with a Gemini call) <span style={{color: "#16a34a"}}>· beginner</span>; an Automated
content-automation script (scripting, APIs, file handling)
<span style={{color: "#16a34a"}}>· beginner</span>.

**Move on when:** you can write a Python script that calls an external API and parses
the JSON, spin up a Streamlit app with an input box and a button, and you have a
GitHub repo with a real README.

## Stage 5 · Advanced & Production RAG

Basic RAG impresses no one in 2026 — companies want robust, accurate, secure RAG.
This stage covers the advanced retrieval techniques and the safety/eval layers that
turn a demo into a product.

**What to learn:** hybrid search (keyword + semantic) and reranking · advanced
patterns — HyDE, Corrective RAG (CRAG), Self-RAG, query rewriting · Text2SQL (let an
LLM query a database safely, with human approval) · caching (Redis) & LLM gateways
for cost and speed · guardrails (input/output filtering, prompt-injection defense) ·
evaluation (faithfulness, relevance, eval sets instead of eyeballing) · orchestrating
all of it with LangGraph.

**Build-along projects:** a Flipkart-style Product Recommender chatbot (RAG + GCP)
<span style={{color: "#d97706"}}>· intermediate</span>; an Enterprise Advanced RAG in
LangGraph — hybrid search, reranking, HyDE, CRAG, Self-RAG, Text2SQL, caching +
guardrails <span style={{color: "#dc2626"}}>· advanced</span>; a Production-grade
cyclic RAG with LangGraph + guardrails + evals
<span style={{color: "#dc2626"}}>· advanced</span>.

**Move on when:** you can add reranking and a guardrails layer to a RAG system,
evaluate a pipeline's answer quality (not just eyeball it), and you're comfortable
orchestrating a RAG flow in LangGraph.

## Stage 6 · Fine-Tuning & Open Models

Sometimes RAG and prompting aren't enough and you need to adapt the model itself.
This stage is lighter than RAG for most learners, but you should understand *when*
and *how* to fine-tune, and how to run open-source models for cost and privacy.

**What to learn:** fine-tuning vs RAG vs prompting — when to use each · building &
formatting instruction/chat datasets · parameter-efficient fine-tuning (LoRA / QLoRA)
· Hugging Face Transformers for loading models and running inference · running open
models (Llama via Ollama/Groq) · evaluating a fine-tune · serving a fine-tuned model
behind an API.

**Build-along projects:** an End-to-End NLP dialogue-summarization system with Hugging
Face <span style={{color: "#d97706"}}>· intermediate</span>; an AI web app with LLM
fine-tuning + CI/CD (fine-tune, ship via cloud + DevOps)
<span style={{color: "#16a34a"}}>· beginner</span>.

**Move on when:** you can articulate when fine-tuning beats RAG (and when it doesn't),
you've run an open-source model and used it in an app, and you've completed at least
one Hugging Face / fine-tuning project.

## Stage 7 · Agentic AI

This is the destination — the focus of 2026 AI engineering: autonomous systems that
use LLMs to **plan, reason, and act** to achieve goals. An agent goes beyond a single
answer: it decides what to do, calls tools, remembers, and can work with other agents. The full breakdown below follows a complete 23-module Agentic AI specialisation — foundations, every major framework, the MCP/A2A protocol layer, security, AgentOps, and multi-cloud deployment.

**What to learn:** agent fundamentals (the ReAct reasoning/acting loop, planning,
goals) · Pydantic for structured agent I/O · async programming for agents · tool /
function calling to give agents abilities · agent memory (short-term vs persistent —
Mem0, LangMem) · frameworks: LangGraph (stateful graphs, workflows — sequential,
parallel, conditional, iterative — and subgraphs), CrewAI (role-based crews), Microsoft
AutoGen, OpenAI Agents SDK, Google ADK · agent persistence (DB-backed memory, streaming,
chat threading) · multi-agent orchestration · agentic RAG · human-in-the-loop approval
and safe autonomy · harness engineering (scaffolding around an agent) · loop engineering
(think → check → retry cycles).

**Build-along projects:** a Stateful Agent in LangGraph + Llama 3
<span style={{color: "#16a34a"}}>· beginner</span>; a Notion ReAct Planner Agent
<span style={{color: "#16a34a"}}>· beginner</span>; an AutoGen data-analyzer crew
<span style={{color: "#16a34a"}}>· beginner</span>; an AI Customer-Support Agent
(RAG + Mem0 memory + tools, FastAPI, Docker, CI/CD)
<span style={{color: "#d97706"}}>· intermediate</span>; an Autonomous Blog-Generation
Agent (LangGraph + FastAPI) <span style={{color: "#d97706"}}>· intermediate</span>;
an Agentic Chatbot (LangGraph + persistence + LangSmith + tools + RAG + HITL + CI/CD
on AWS) <span style={{color: "#d97706"}}>· intermediate</span>; TripMate AI —
Multi-Agent Travel Planner (Groq + LangGraph + PostgreSQL + FastAPI)
<span style={{color: "#d97706"}}>· intermediate</span>.

**Move on when:** you can build an agent with tool calling and persistent memory,
you've built at least one multi-agent system (CrewAI / AutoGen / LangGraph), and you
understand human-in-the-loop and when to add approval gates.

### The Agentic AI specialisation (full 23-module curriculum)

Stages 7–8 mirror a complete, production-focused **Agentic AI** curriculum. If you
want one ordered path through the agentic era — foundations, every major framework,
the 2026 protocol layer (MCP + A2A), security, AgentOps, and multi-cloud deployment —
follow these 23 modules in order. Each phase builds on the last.

**Phase A · Foundations & structured outputs**

| # | Module | What you learn |
| --- | --- | --- |
| 1 | Introduction to Agentic AI | What actually makes something an agent; Agentic AI vs Generative AI vs AI agents; multi-agent systems; the core design patterns (ReAct, Supervisor, Swarm, Pipeline, Mesh); the agentic protocol layer; the framework landscape; and how reasoning models change agent behaviour. |
| 2 | Pydantic — Data Validation & Structured Outputs | Typed, validated tool inputs and model outputs — the backbone of reliable tool calling and structured agent responses. |

**Phase B · Core frameworks**

| # | Module | What you learn |
| --- | --- | --- |
| 3 | LangChain & LCEL | The framework and its expression language for composing model + tool pipelines. |
| 4 | LangGraph — Stateful Agent Workflows | Modelling agents as stateful graphs — nodes, edges, branching, loops, and memory. |

**Phase C · The protocol layer (2026)**

| # | Module | What you learn |
| --- | --- | --- |
| 5 | MCP — Model Context Protocol | The open standard for connecting agents to tools and data; building your own MCP servers. |
| 6 | A2A — Agent-to-Agent Protocol | Wrapping agents as services that talk to each other across frameworks and vendors. |

**Phase D · Retrieval & context**

| # | Module | What you learn |
| --- | --- | --- |
| 7 | RAG & Agentic RAG | From basic retrieval to agents that decide when and what to retrieve, and can retry. |
| 8 | Context Engineering | Deciding what goes in the window — token budgeting, dynamic assembly, and the memory stack (short-term, long-term, episodic, semantic, procedural). |

**Phase E · The framework landscape (learn to pick the right tool)**

| # | Module | What you learn |
| --- | --- | --- |
| 9 | OpenAI Agents SDK | OpenAI's native agent framework — handoffs, tools, and guardrails. |
| 10 | CrewAI — Multi-Agent Collaboration | Role-based crews of agents that divide and coordinate work. |
| 11 | Google ADK — Agent Development Kit | Google's agent kit and deployment to Vertex AI. |
| 12 | AWS Strands Agents SDK | Building and deploying agents (and swarms) on AWS. |
| 13 | Azure AI Foundry & Semantic Kernel | Microsoft's agent stack on Azure. |
| 14 | LlamaIndex — Data-Centric Agents | Data-first agents and workflows over your own sources. |
| 15 | Claude Code — Agentic Coding | Agentic coding workflows with Claude Code. |
| 16 | n8n — AI Workflow Automation | Wiring agents into automated workflows, low-code. |
| 17 | LangFlow — Low-Code Agent Builder | Prototyping agent flows visually on a canvas. |
| 18 | AutoGen — Conversational Multi-Agent | Microsoft AutoGen's conversational multi-agent framework. |

**Phase F · Security, ops & deployment**

| # | Module | What you learn |
| --- | --- | --- |
| 19 | Agent Security, Guardrails & Evaluation | The agentic attack surface (prompt injection, tool misuse, data exfiltration); defences (NeMo Guardrails, Guardrails AI, tripwires, sandboxing); trajectory-based eval and LLM-as-judge. |
| 20 | AgentOps — The Full Observability Lifecycle | Session replay, tool-call tracing, cost tracking, and evaluation with AgentOps SDK, LangSmith, Opik, and Langfuse. |
| 21 | CI/CD, Deployment & Production Serving | Dockerised services, GitHub Actions pipelines, and serving with FastAPI / BentoML across ECS, Cloud Run, Vertex AI, Azure Container Apps, and Lambda. |

**Phase G · Production & capstone**

| # | Module | What you learn |
| --- | --- | --- |
| 22 | Designing Multi-Agent Systems in Production | Supervisor, Swarm, Pipeline, and Hierarchical patterns; handoffs, shared state, parallel execution, checkpointing, and human-in-the-loop gates. |
| 23 | Enterprise Capstone — Multi-Cloud & Local Agentic Architectures | End-to-end portfolio builds across AWS, GCP, Azure, and a fully local (Ollama + Chroma) stack. |

> **How this maps to the roadmap:** Phases A–E deepen **Stage 7 (Agentic AI)**;
> Phases F–G are **Stage 8 (AgentOps, MCP & Production)**. Modules 5–6 (MCP / A2A) are
> the protocol layer that ties every framework together.

## Stage 8 · AgentOps, MCP & Production

The final stage turns your agents into reliable, observable, deployable systems — the
difference between a cool demo and something a company will pay for — plus the two
foundational 2026 protocols: **MCP** and **A2A**.

**What to learn:** MCP (Model Context Protocol — the standard way to connect agents to
tools/data) · A2A (Agent-to-Agent communication) · AgentOps & observability (tracing
and debugging with LangSmith, Langfuse, Opik) · agent evaluation (DeepEval, eval sets)
· agent security (prompt-injection defense, guardrails, least-privilege tool access) ·
deployment (Docker, CI/CD, cloud) · production monitoring (Prometheus, Grafana, ELK).

**Build-along projects:** MCP with AutoGen — connect an agent to Notion
<span style={{color: "#16a34a"}}>· beginner</span>; Build & deploy agents to the cloud
with Google ADK <span style={{color: "#16a34a"}}>· beginner</span>; an Advanced AI
GitHub PR Reviewer (event-driven LangGraph + FastAPI + Prometheus/Grafana + Langfuse)
<span style={{color: "#dc2626"}}>· advanced</span>; a Multi-Agent AI system with MCP +
Supervisor + Guardrails + HITL
<span style={{color: "#dc2626"}}>· advanced</span>; a Self-Correcting Multi-Agent App
deployed on DigitalOcean Serverless
<span style={{color: "#d97706"}}>· intermediate</span>; a Real-Time Voice AI Agent with
RAG <span style={{color: "#d97706"}}>· intermediate</span>.

**Move on when:** you've connected an agent to a tool using MCP, deployed an agentic
app to the cloud with observability wired in, and you can talk through security and
evaluation for an agent in an interview.

## Suggested pace

At ~10–15 hrs/week, a realistic pace through the track:

| Stage | Focus | Suggested time |
| --- | --- | --- |
| 0 | Python & setup | 2–3 weeks |
| 1 | LLM basics | 2 weeks |
| 2–3 | Calling models, prompting & apps | 2–3 weeks |
| 4 | RAG (core) | 4 weeks |
| 5 | Advanced / production RAG | 4 weeks |
| 6 | Fine-tuning & open models | 2 weeks |
| 7 | Agentic AI | 6 weeks |
| 8 | AgentOps, MCP & production | 4 weeks |

deployed, documented projects** on GitHub.
